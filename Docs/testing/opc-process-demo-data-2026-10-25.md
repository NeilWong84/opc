## 存储与写入边界

PG 保存需求、版本、评审、关系、消息、文件元数据及关联；实际字节沿用 `OPC_STORAGE_ROOT`（本机为 `BackendService/.local/files`）的随机私有键，不能作为公共静态目录暴露。原文件名与 storage key 分离，下载逐次鉴权。后续用户计划购置 OSS，届时另行接入存储后端并迁移／验证字节，不在本批预定供应商或开通服务。

本机批次目录 `BackendService/.local/process-demo-20261025` 被既有 `.local/` 规则忽略，包含：

- `assets/`：20 份有名称的源附件（另有工具检查产物，不上传）；
- `asset-manifest.json`：每份源附件的大小、哈希和实际检查依据；
- `seed-manifest.json`：新增业务及文件 UUID，不包含账号密码；
- `before-seed.json`：原需求版本快照、密码哈希的摘要；
- `verification.json`：提交后实际库计数与 API 验证结论；
- `qa/`：渲染图、媒体参数、Office 验证报告及源码单测记录；
- `build/`：临时构建与捆绑运行时链接；仅供本批验证的 LibreOffice 安装包、解包工具及解包运行目录在检查完成后已清理，未注册为 OPC 文件转换服务。渲染图和日志仍保留于 `qa/`。

需求、澄清、范围、评审、发布、合作、确认、交付、质检与验收通过原有业务 API 在同一受限数据库事务中写入，数据库约束逐次检查。仅种子进程临时允许 `record_confirmed` 录入合成关系，不改运行服务的 `disabled` 默认。

合成消息由可信种子装载器写入：先使用正常 API 验证对应作者有权读取会话，再由共享参与者函数加入作者，设置可信事务账号，以 `clock_timestamp()` 插入消息。数据库消息触发器与审计照常执行。这样避免同一原子种子事务的 `now()` 导致全部消息时间相同、显示顺序随机；不是新增允许客户端指定作者／时间的 API。

种子只接受有标记的本机 opc_dev／opc_integration 与受限应用身份，并核对凭据归属和实际登录身份。原件必须匹配已检查清单。已初始化批次重复执行时检查需求、附件记录及磁盘哈希，只验证而不重建。失败回滚数据库并清理本批已跟踪的上传键；若进程在事务提交前被强制终止，磁盘孤儿文件仍须按后续维护策略处理，不能宣称文件系统具有数据库事务性。
