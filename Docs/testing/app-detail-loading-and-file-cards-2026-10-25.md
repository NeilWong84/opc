# 手机详情定向读取与附件卡片（2026-10-25）

## 用户要求与问题定位

用户反馈部分需求进入详情很快，部分持续转圈，且尚未进入附件预览页；明确要求先解决读取整个账号的问题，再优化附件、资料和参考文档样式。

原 `ApiOpcRepository.refreshItem` 直接调用账号 `refresh`，串行读取所有需求详情、合作详情和会话消息。原详情页在 `app.busy` 时直接退出初次加载，未安排后续读取，存在一直显示加载动画的路径。这两处均与音视频解码无关。

## 已实现

- 详情重新校验手机身份，只读取当前需求、当前需求的最新合作和当前需求的会话消息；不读取草稿、通知或其他需求详情，不请求附件预览／下载字节。
- 手机合作列表和会话列表新增可选 `request_id`，服务端在原有权限条件内、分页之前过滤。无此参数时保留工作台原列表语义。管理员会话列表也支持相同过滤。
- 发送反馈、答复澄清、确认条款、提交交付及验收后的数据更新仅刷新当前需求；幂等重试仍保留原操作参数和版本。
- 详情等待正在执行的前台操作结束后继续加载；后台的工作台路由不再因为应用恢复前台而触发账号全量刷新。回到工作台时仍按工作台职责刷新汇总。
- 保留账号切换／退出及并发刷新保护；当前需求读取失败后不继续展示旧详情。单项恢复成功不把此前失败的账号完整快照伪装成有效。
- 私有附件、参考资料及交付资料复用彩色卡片，显示文件名称、类型封面、大小及适用的安全检查状态；Word／Excel／PPT 分别使用 W／X／P 标记，PDF、图片、音频、视频、文本与压缩包使用对应图标。支持中日双语和亮暗主题。
- 封面为本地绘制的**文件类型封面**，音频使用波形图标、视频使用播放图标；不是实际视频首帧、音频波形分析结果或文档首页缩略图。不会为了列表封面下载原件或触发文档转换。点击文件后仍进入真实鉴权预览与原件保存流程。

## 实测与验证

在当前本机 `8001 → 55440/opc_integration` 链路，用临时客户会话进行只读测量，完成后注销该会话，未改动业务记录：

| 场景 | HTTP 读取次数 | 单次测量耗时 |
| --- | --- | --- |
| 原账号完整刷新：14 条需求、7 个合作、10 个会话 | 37 | 2,298 ms |
| `REQ-00001013`：12 个私有附件，无合作／会话 | 4 | 180 ms |
| `REQ-00001003`：1 个合作和1个会话 | 6 | 398 ms |

耗时为本机接口链路采样，不是所有网络环境的手机端渲染承诺。已核对运行中的 OpenAPI 包含 `request_id`，两个过滤结果均只含选定需求；`/health/ready` 返回 200。

- 后端 Ruff 通过；独立 `55439/opc_test_*` PostgreSQL 实例 **145 项测试通过**，覆盖过滤先于分页、无权账号、未知需求及非法 UUID。
- Flutter 静态检查无问题，全量 **347 项测试通过**；普通入口 `lib/main.dart` 的真实 API APK 构建成功，已覆盖安装并启动于可见的 `emulator-5554`。新增测试覆盖详情请求范围、新合作与当前反馈、失败重试、退出／并发防护、忙碌时进入详情、后台工作台不刷新，以及小屏大字、两语言两主题和点击后才读取文件。
- 彩色卡片实际控件已渲染并人工查看亮暗截图。可选截图测试通过 `OPC_CAPTURE_FILE_CARDS=1` 启用；本地字体路径仅通过环境变量传入，正常测试不依赖系统字体文件。
