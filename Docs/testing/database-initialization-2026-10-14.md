## 3. 迁移与本地保护验证

- **重复初始化**：重新执行后四个迁移均显示 `Already applied, unchanged`，没有重新应用迁移或重复写字典。
- **校验值篡改模拟**：不修改历史文件，向迁移包装器传入错误 SHA-256；psql 以错误码 3 拒绝，在执行迁移前停止。
- **目标保护**：传入 `-DatabaseName accounts`，脚本在连接前拒绝。
- **真实双连接迁移锁**：连接 A 在事务中持有 `(184920,2)` advisory lock，连接 B 的 `pg_try_advisory_xact_lock` 返回 false；A 回滚退出后，B 返回 true。测试没有写业务数据。
- **结构检查**：[inspect.sql](../../DB/tests/inspect.sql) 通过，确认迁移记录、中文/日语字典、表数量、空业务表和 PUBLIC 权限。

初始化检查过程中发现一次 PowerShell 环境恢复问题：未设置的 `PGCONNECT_TIMEOUT` 被恢复为空字符串，影响同一进程后续 psql 调用；已针对“原先不存在的变量应移除”修复脚本并复验。该问题不影响已经成功提交的 SQL 迁移。

本机原始检查输出保存在 `DB/.local/`（被忽略，不含连接密码）；长期结果以本文和可重复执行脚本为入口。
