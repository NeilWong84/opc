# OPC 本机服务监控器设计

日期：2026-10-22  
状态：已按本设计实现并完成源码、自动化测试、Windows `onedir` 打包与只读本机验证；生产部署不在范围内。验证见 [2026-10-22 记录](../testing/opc-service-monitor-2026-10-22.md)。

## 1. 目标与定位

在 `Tools/ServiceMonitor` 新建一个面向 OPC 本机开发与联调环境的 Windows 桌面运维工具。工具使用 Python 3.12、PySide6 与 Qt Widgets，为开发人员提供统一的服务启停、就绪检查、运行日志查看和历史检索入口。

该工具不是 OPC 的第三个业务产品端，不改变当前 Flutter 手机端、Vue 管理后台和统一 BackendService 的产品边界。Flutter APP 完全不纳入本工具，不提供设备、ADB、Flutter 启停或日志入口。

首版管理范围固定为：

- `FrontendAdmin`：Vue/Vite，`127.0.0.1:5180`。
- `BackendService`：FastAPI/uvicorn，`127.0.0.1:8001`。
- 本机持久联调 PostgreSQL：`127.0.0.1:55440/opc_integration`。
- BackendService 管理 API 提供的 OPC 业务审计记录。

成功标准：用户可从一个窗口安全地启动、停止并判断上述三个服务是否就绪；实时日志按来源分 Tab 展示；最近 7 天的本机运行日志可按来源、时间、级别及关键词检索；管理员登录后可检索业务审计记录；可从独立 Windows 桌面包启动工具。

## 2. 非目标

- 不启动、停止、构建或监控 Flutter APP。
- 不新增业务 API，不改变 OPC 审核、发布、接单、交付或权限规则。
- 不自动运行 `seed-demo.py`，不创建或重置演示账号和业务数据。
- 不监控生产环境、远程主机、容器或云服务。
- 不采集浏览器 DevTools 控制台日志；FrontendAdmin Tab 只包含 Vite/npm 进程输出。
- 不启用 PostgreSQL 全量 SQL statement 日志，不记录完整 SQL 参数。
- 不读取或展示 `.env`、数据库密码、演示账号密码、Bearer Token、私有上传文件或 PostgreSQL 数据文件。
- 不接管由其他终端或工具启动的进程。
- 首版不提供系统托盘常驻、Windows 服务安装或后台守护进程。

## 3. 技术方案

采用单进程 PySide6 Qt Widgets 应用。Qt 主线程只处理界面；进程输出、文件跟踪、HTTP 健康检查、审计请求和日志索引写入均通过受控的异步任务或工作线程完成，结果以 Qt 信号返回主线程。

主要组件：

| 组件 | 职责 |
| --- | --- |
| `MainWindow` | 顶部全局操作、服务状态卡、日志 Tab、审计登录和错误提示 |
| `ServiceSupervisor` | 按依赖顺序启停服务，记录并校验本工具拥有的进程 |
| `ServiceDefinition` | 固定服务目录、命令、端口、健康检查和停止策略 |
| `HealthMonitor` | 后台执行端口及 HTTP 检查，输出统一状态 |
| `LogCollector` | 增量读取 stdout/stderr 与允许的日志文件，处理流式解码 |
| `LogRedactor` | 在显示和写入索引前遮盖凭据及敏感连接信息 |
| `LogStore` | 使用本地 SQLite 保存已脱敏运行日志索引与允许日志文件游标；不保存管理员会话或审计正文 |
| `AuditClient` | 管理员登录、内存 Token、审计分页读取及 401 失效处理 |
| `SettingsStore` | 保存 OPC 根路径、窗口状态和非敏感界面偏好 |

项目根使用确定顺序识别：先读取已保存的非敏感路径；源码模式再从当前文件的父目录定位；Windows 打包模式再检查 `D:\OPC`；仍未找到时要求用户选择。只有同时存在 `BackendService`、`FrontendAdmin`、`DB` 和根 `README.md` 才接受为项目根。项目位置可修改，修改时重新执行依赖检查。

配置、SQLite 索引和监控器自身日志保存在 `%LOCALAPPDATA%\OPC\ServiceMonitor`。测试可通过专用环境变量覆盖该目录，产品界面不允许将其指向 BackendService 的 `.local` 或 PostgreSQL 数据目录。

## 4. 服务生命周期

### 4.1 启动顺序

“全部启动”严格执行：

1. 在 `BackendService` 工作目录调用现有 `.venv\Scripts\python.exe scripts\provision-local-integration.py start`。
2. 等待 PostgreSQL 进程状态正常；不将 `start` 命令用于定时轮询。
3. 在 `BackendService` 工作目录调用 `scripts\start.ps1 -Port 8001`。
4. 等待 `GET http://127.0.0.1:8001/health/live` 成功，并要求 `GET /health/ready` 返回就绪。
5. 在 `FrontendAdmin` 工作目录调用 `npm run dev`。
6. 等待 `GET http://127.0.0.1:5180/` 成功并包含当前 `<title>OPC Admin</title>` 页面标识。

任何一步失败或超时都停止后续步骤，保留已经启动的前置服务并明确显示部分成功状态，不自动回滚或删除数据。用户可检查日志后单独重试或执行全部停止。

### 4.2 停止顺序

“全部停止”严格执行：

1. FrontendAdmin。
2. BackendService。
3. PostgreSQL，调用现有 `provision-local-integration.py stop`，使用其安全标记和目标目录校验，并保留数据。

前端与后端先请求普通终止；超时后仅对本工具记录且重新验证过 PID、启动时间和可执行路径的进程树执行强制停止。wrapper 在首次 listener 检查前退出时，只有创建时间有效、父链逐节点身份可验证且父 PID 未复用，才恢复 listener 所有权；否则按外部实例保护。不得按进程名批量结束 `node.exe`、`python.exe`、`postgres.exe` 或其他共享进程。

### 4.3 所有权与外部实例

启动前先检查端口和健康端点。若目标端口已由非本工具拥有的进程使用，则状态为“外部实例”：允许显示端口及健康结果、打开页面和读取允许的文件日志，但禁用停止按钮，也不把该进程加入本工具的所有权记录。

本工具只在当前会话管理自己创建的进程。退出时若仍有自有进程，弹窗要求“停止并退出”或“取消”；首版不允许退出后继续保留自有进程。异常退出后的遗留进程在下次启动时按外部实例处理，不根据旧 PID 记录直接接管。

### 4.4 状态模型

三个服务统一使用：已停止、启动中、运行但未就绪、已就绪、外部实例、停止中、失败。进程存在、端口监听、HTTP 存活和 BackendService 数据库就绪是不同事实，界面分别展示，不能仅凭端口判定服务可用。

默认检查间隔为 2 秒；连续检查使用单飞机制，不叠加并发请求。单次网络检查超时 3 秒。启动超时默认 PostgreSQL 30 秒、BackendService 30 秒、FrontendAdmin 30 秒；这些值可在非敏感设置中修改并限制在 5 至 120 秒。

## 5. 界面设计

主窗口采用“顶部控制栏 + 服务状态卡 + 日志工作区”布局。

顶部控制栏包含：全部启动、全部停止、刷新状态、打开管理后台、打开 Swagger、设置。打开管理后台指向 `http://127.0.0.1:5180/#/dashboard`，Swagger 指向 `http://127.0.0.1:8001/docs`。

FrontendAdmin、BackendService、PostgreSQL 各有一张状态卡，显示统一状态、端口、PID（仅在可靠识别时显示）、运行时长、最近健康结果、独立启停按钮和最近错误。界面不根据 FrontendAdmin 的启动状态推断业务联调已经成功，只呈现实际健康结果。

日志工作区固定包含：

- 全部日志
- 前端
- 后端
- PostgreSQL
- 业务审计

每个运行日志 Tab 提供关键词、起止时间、级别、来源、大小写匹配和正则表达式筛选；支持暂停自动滚动、跳到最新、复制选中内容、清空当前视图和导出当前筛选结果。无效、结构高风险或计数量词过大的正则在编译前只显示校验错误，不触发查询；实时匹配超时后熔断当前查询并明确提示，修改查询后恢复。清空视图不删除 SQLite 历史或源日志文件。

业务审计 Tab 在未登录时显示管理员邮箱和密码输入框，通过 `/api/v1/admin/auth/login` 建立管理会话；登录成功后立即清空密码控件，Token 只保存在内存。界面支持刷新、分页加载、时间、操作者、对象、操作和关键词筛选。退出登录、Token 失效或程序退出时清除 Token 和当前审计缓存。

界面只提供简体中文。操作期间按钮按状态禁用，防止同一服务收到并发启停命令。

## 6. 日志来源与存储

### 6.1 来源

| 来源 | 采集方式 |
| --- | --- |
| FrontendAdmin | 本工具启动的 `npm run dev` stdout/stderr |
| BackendService | 本工具启动的 PowerShell/uvicorn stdout/stderr |
| PostgreSQL | 明确路径 `.local/integration/postgres.log` 和 `.local/integration/provision.log` 的增量读取 |
| 业务审计 | 管理员身份调用 `/api/v1/admin/audit-events` 分页读取 |

只允许以上明确来源。程序不递归遍历 `.local`，不导入移动端测试日志，也不根据通配符读取未知扩展名文件。

### 6.2 处理链路

运行日志处理顺序为：字节块 → 增量解码 → 行切分 → ANSI 控制序列清理 → 时间与级别归一化 → 敏感信息脱敏 → 界面 → SQLite。

终端流优先使用严格 UTF-8；无法解码的字节以替换字符保留并增加解码警告，不能因单行损坏中断后续采集。新启动的 Python 子进程设置 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8` 和 `PYTHONUNBUFFERED=1`。来源未提供明确级别时标记为 `INFO`，stderr 默认标记为 `ERROR`，但保留原始 stream 字段。

脱敏在任何持久化之前执行，至少覆盖 Authorization/Bearer Token、常见 password/secret/token 键值、以敏感后缀结尾的环境变量或配置键、PostgreSQL URL 中的密码和命令行凭据形式。导出只使用已脱敏内容。

### 6.3 SQLite 索引

SQLite 保存运行日志的时间、来源、stream、级别、脱敏消息和源文件游标；对消息建立 FTS5 全文索引。使用单一写入工作线程、批量事务和流式 `executemany` 参数，避免 Qt 主线程阻塞及重复构造大参数列表。允许文件每轮最多读取 2 MiB、生成 10,000 条完整记录；实时界面使用 512 条有界队列和单飞批量通知，溢出只影响即时显示并合并提示，已持久化历史不受影响。历史显示与导出查询默认最多累计 8 Mi 字符正文，达到预算后保留已收集结果并提示，避免极端长行结果造成无界内存增长。每天启动时及运行中定期删除早于 7 天的记录并整理无效全文索引项。

SQLite 不复制业务数据库。业务审计以服务端为事实来源，只在当前登录会话中缓存当前页和筛选结果，不持久化审计正文。SQLite 丢失或损坏时先改名隔离，再建立空索引；不得影响 OPC 服务启动或业务数据。

## 7. 安全与权限

- 管理员密码只用于本机 HTTP 登录请求，不写日志、配置、SQLite、命令行或异常详情。
- 管理 Token 只存在进程内存；不写 `QSettings`、剪贴板或导出文件。
- 不读取 `.env` 或 `.local/demo-credentials.json`，也不提供自动演示管理员登录。
- 不展示数据库连接串、数据库密码或 `instance.json` 的密码字段。需要实例信息时只使用已知安全路径和现有脚本校验。
- 进程命令在启动前使用固定模板和参数列表，项目根必须通过结构校验；不把用户输入拼接为 PowerShell 命令文本。
- 日志导出由用户显式选择目标，导出前再次经过脱敏器；导出文件不包含未加载的源日志或审计 Token。
- 本工具只适用于本机开发联调。8001、5180 和 55440 均保持绑定 `127.0.0.1`，不提供修改为公网监听的界面。

## 8. 错误处理与恢复

- 缺少后端虚拟环境、Node/npm、前端依赖、PostgreSQL 18 工具或项目目录时，在依赖检查中逐项显示路径、原因和修复建议；不会自动安装依赖。
- 服务命令返回非零、健康检查超时、日志文件被截断或轮转、SQLite 锁冲突和 API 401/403 均使用稳定的用户可读错误，不显示密码或完整请求头。
- 文件日志跟踪使用文件标识、大小和游标；遇到截断或轮转从新文件开头继续，并记录一条监控器事件。
- 业务审计 401 清除 Token 并返回登录状态；403 保留登录状态并提示账号无审计权限。
- 单个日志来源失败不停止其他来源或服务健康检查。
- 启停任务可取消等待，但取消不等于服务已停止；界面必须重新检查实际状态。

## 9. 测试策略

实现遵循测试先行。自动化测试不启动或停止真实 OPC 服务，使用临时目录、假子进程、本地测试 HTTP 服务和测试 SQLite。

测试至少覆盖：

- 项目根识别、固定命令和工作目录。
- PostgreSQL → BackendService → FrontendAdmin 的启动顺序及反向停止顺序。
- 前置步骤失败时阻止后续启动。
- 自有进程与外部实例区分，PID 复用和路径不匹配时拒绝停止。
- 健康检查超时、错误响应和状态转换。
- UTF-8 多字节跨块、CRLF/LF、ANSI、超长行和非法字节处理。
- Token、密码和数据库 URL 在显示、索引及导出前均被遮盖。
- 普通关键词、大小写、时间、级别、来源和无效/有效正则筛选。
- 7 天保留边界、SQLite 损坏恢复和文件轮转游标。
- 审计登录成功、401、403、退出及 Token 不持久化。
- Qt 服务按钮、Tab、暂停滚动、清空视图、退出确认和错误提示。
- 打包后从非源码工作目录启动并选择 OPC 根目录。

实现完成后执行单元测试、Qt 组件测试、静态检查和 PyInstaller 构建。自动化通过后，再在端口未被外部实例占用的前提下执行一次真实本机冒烟：启动三个服务、检查 55440/8001/5180、验证各日志 Tab 与检索、按反向顺序停止，并确认 PostgreSQL 数据目录和既有业务记录未被清空。若发现外部实例则只做只读健康检查，不停止或接管。

## 10. 打包与交付

使用 PyInstaller 在 Windows 上生成 `onedir + windowed` 包，主程序名为 `OPCServiceMonitor.exe`。先验证目录包，再考虑未来是否需要安装器；首版不生成 onefile。

桌面包包含监控器自身 Python 与 Qt 运行时，但不包含或复制 BackendService 虚拟环境、Node.js、npm、FrontendAdmin 依赖、PostgreSQL、数据库或业务文件。工具始终调用所选 OPC 项目中的真实依赖，并在启动前验证它们。

交付内容：

- `Tools/ServiceMonitor` 源码、锁定依赖、测试、构建脚本和 README。
- Windows `onedir` 桌面包。
- 使用说明、依赖检查、日志位置、安全边界和故障排查。
- 根 README、`Docs/README.md` 与 `Docs/project-context.md` 的事实同步。
- 实际测试和本机冒烟结果记录；未执行的检查不得写为通过。

## 11. 验收条件

1. Flutter APP 的命令、状态和日志在程序及配置中均不存在。
2. 全部启动按数据库、后端、前端顺序执行，并以真实就绪结果更新状态。
3. 全部停止按前端、后端、数据库顺序执行，数据库保留原数据。
4. 外部占用 5180、8001 或 55440 时不被停止或接管。
5. 五个日志 Tab 可用；运行日志可实时显示并检索最近 7 天历史。
6. PostgreSQL 只读取两个允许日志文件；业务审计使用管理员 API 且凭据不落盘。
7. 关键词、时间、级别、来源、大小写和正则筛选均有自动化验证。
8. 日志显示、索引和导出均不出现测试中注入的 Token、密码或连接串秘密。
9. GUI 在服务启动、健康超时、日志持续写入和历史检索时保持响应。
10. Windows `onedir` 包可从非源码目录启动、选择项目根并完成依赖检查。
