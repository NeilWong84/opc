## 客户提交与任务大厅

2026-10-26 用户要求将提交开发需求的“期望完成时间”改为日期选择控件。真实表单现为只读日期字段，点击字段或日历图标打开跟随中日文及浅深主题的日历；新选日期按 `YYYY-MM-DD` 写入原 `timing_text`，不附加时分或时区转换。已有ISO日期草稿恢复选中日，旧文字草稿保留原文，正式提交前必须选择具体日期；取消不修改原值，未完整输入仍可保存草稿。本轮仅调整手机表单，后端及数据库契约不变。见[日期选择验证](testing/app-request-completion-date-2026-10-26.md)。

2026-10-26 用户要求客户需求支持按开发端（Web、网站、Android、iOS、桌面）和开发类型（CRM、HR 人力、车辆管理、收银销售、OA、通用信息化）分类检索，并支持中日文。本轮新增 `008_request_classifications`：双语字典保存稳定代码、排序与启用状态；草稿及原文版本分别关联一个主要开发端、一个开发类型，可不选。客户需求页两维可与原状态筛选组合；表单保存及恢复分类，界面语言只改变字典显示名称。存量需求保留 NULL／未分类，不从原文自动推断。用户先选择交付代码与包，随后明确要求更新；现已备份并完成001—008迁移、重启8001，真实鉴权分类接口通过。经用户授权与承接者聊天协调后，包含两边源码的普通包已统一安装到模拟器，设备与分类交付快照SHA256一致，已核验无测试入口或本轮测试凭据。手机当前为承接者登录状态，客户分类需使用客户账号进入需求页。详见[分类实施与验证](testing/app-client-request-classifications-2026-10-26.md)。

客户可以注册、登录并自行提交需求。所有需求必须经过后台审核，审核包括合规性与技术整理；客户不需要具备技术知识，由内部人员帮助梳理目标、范围、技术依赖、交付物和验收标准。

**审核通过后才能发布到任务大厅；未审核通过的需求在大厅不可见。** 提交需求、审核通过、发布大厅、确定承接者和合作执行是不同动作。客户可以在自己的需求页查看待审内容及进展，后台按权限处理，不能将大厅不可见误解为客户无法查看本人需求。

当前方案建议保留客户原始描述、整理稿、审核及发布版本，重大变化重新审核；AI 只辅助，不代替内部审核。大厅展示范围、是否需客户确认整理稿才发布仍需细化；承接前的双方确认方式按下节 2026-10-26 最新决定执行，不能据此扩展为公开竞标。

## 当前承接者与未来认证

2026-10-26 用户明确承接流程：承接者首页独立汇总沟通中、进行中、已交付项目，单独提供可检索的任务大厅。仅当前双审发布、未进入合作的任务可承接；承接者与需求客户按人隔离沟通，提出绑定当前发布版本的范围与条款；**客户先在手机确认本次范围与条款，承接者再一键“承接项目”**，项目立即进入执行中并归属该账号。不是由承接者代替客户确认，也不再把本流程列为待选政策。服务端检查内部授权、双方身份、提案及发布版本、并发和幂等，防止重复归属。管理端 `record_confirmed` 保留历史录入用途，与新的自主承接接口分别处理。实现及验证入口见[承接者工作台与自主承接](development/provider-claim-workflow.md)。

当前承接者为内部受控人员，给他们指定系统账号登录接单。指定的是系统账号，**不等于用户已经决定每一单都必须由后台派给某人**。内部账号管理和订单接单方式分别设计。

普通客户注册不自动取得承接权限；内部账号状态、接单授权与正式认证资格分开记录。未实际考核的内部账号不能显示“OPC 已认证”。

后续承接者需要通过考核，成为正式 OPC 认证承接方后才能接单。考核内容、评定、资格有效期、复核、撤销与当前内部人员的转入方式尚待定义；当前不推定已建立考试或认证系统。

“内部”不自动代表劳动关系、国籍或签约主体；日本国内业务也不自动代表数据处理全部发生在日本。
